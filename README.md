# prune-cache-map

Every location Prune looks at, and why it is safe to clear.

[Prune](https://prune.digitalarc.lk) is a disk cleaner for Mac and Windows. This repository is the list of folders and rules its scanner uses, written down so you can check them before you trust a cleaner with your disk. It is derived from the app's source code and describes paths and rules only; it contains no code.

If a location is not in this list, Prune's scanner does not look there. The one exception is the Explore Disk view, where you can browse any folder yourself and tick things by hand. Those picks are your own choice and still pass the refusals listed below.

## How to read `paths.json`

`paths.json` is an array. Each entry has:

| Field | Meaning |
|---|---|
| `id` | Stable name for the entry. Starts with `macos-`, `windows-` or `both-`. |
| `category` | The area it belongs to. Same headings as the tables below. |
| `platform` | `macos`, `windows` or `both`. |
| `path` | The location, as a pattern. `~` is your home folder (`%USERPROFILE%` on Windows). `%LOCALAPPDATA%`, `%APPDATA%` and `%WINDIR%` are the usual Windows folders. `<name>` marks a part that varies, such as `<project>` or `<cache folder>`. |
| `what_it_is` | What the location holds. Where the entry is a rule rather than a fixed path (for example `node_modules` inside idle projects), this describes the rule. |
| `safe_to_delete_because` | Why removing it does not lose anything you need. |
| `cost_of_deleting` | What you pay afterwards, for example "re-downloads on next use" or "rebuilt on next build". |
| `preselected` | `true` if Prune ticks it by default after a scan. Nothing is removed until you review the list and press Clean. |
| `check_command_macos`, `check_command_windows` | A read-only command that shows how big the location is on your machine. `null` where the entry does not apply to that system. Windows commands print gigabytes. |

A few entries are not folders on disk (Docker prunes, Xcode simulators, Time Machine snapshots, the Windows Recycle Bin and registry start-up entries). Their `path` describes what is queried, and the check command is the closest read-only equivalent.

Prune only reports what exists. A cache that is missing on your machine simply does not appear.

## What Prune refuses to delete

These checks run when you press Clean, after scanning. They apply even if an item is ticked, and they are enforced in the app's deletion code, not just hidden in the interface.

- **Anything on your Keep List.** Paths you add are skipped, along with everything beneath them.
- **Protected names.** Any path that ends with, or sits inside, `globalStorage/state.vscdb`, `globalStorage/state.vscdb.backup` (the chat and session history that Cursor, VS Code, VSCodium, Windsurf and similar editors keep) or `claude-code-sessions` (Claude Code session transcripts). These are refused outright.
- **Any path containing `..`.** A path that climbs out of a folder with `..` is refused, because it could point outside the place it appears to start in.
- **Anything outside the allowed roots.**
  - On Mac, only items strictly inside your home folder, strictly inside `/Library/Logs`, beneath a disk you have attached, or an `Install macOS <name>.app` in `/Applications` whose bundle identifier starts with `com.apple.InstallAssistant`.
  - On Windows, only items inside your user profile, inside `%WINDIR%\Temp`, exactly `%WINDIR%\SoftwareDistribution\Download`, exactly the Delivery Optimization cache folder under `%WINDIR%\ServiceProfiles\NetworkService`, or beneath a disk you have attached.
  - The check requires a separator after the folder name, so `/Users/me` does not admit `/Users/me2`.
- **The user profile itself.** Your home folder (Mac) or user profile folder (Windows) is never removable as a whole.
- **Drive roots.** A bare attached-disk root, and on Windows any bare drive root such as `C:\`, is refused. Only things beneath a disk are allowed.
- **The Windows directory.** `%WINDIR%` itself is refused. Only the folders named above inside it are allowed; the rest of it is never opened up.
- **Files in use.** Antigravity files modified in the last two hours are skipped, and files another app has open are reported and left alone.

Limits inside the scanners themselves:

- On Mac, the folders `CloudStorage` and `Mobile Documents` (iCloud and similar) are never walked.
- Disks other than the startup disk are not scanned until you choose them. On Mac, network mounts, read-only volumes and Time Machine disks are not counted as attached disks, so nothing on them is removable. On Windows only fixed and removable drives count.
- WSL2 disk images (`ext4.vhdx`) are deliberately never scanned, because deleting one destroys the Linux install inside it.
- Claude Code session transcripts are offered only after 30 days idle, never include each project's `memory` folder, and are never ticked.
- Git cleanup touches only `refs/original/*` and a `refs/stash` with no stashes behind it. It never runs a history rewrite, never touches a remote, and leaves repositories with real stashes alone.
- Duplicate finding ignores symlinks and hard-linked files, and the review screen will not let you remove every copy of a set.
- Start-up entries are flagged only when the program they launch is an absolute path that is provably missing from a disk that is present.

## Your own files

Large and old files in your Downloads, Desktop and Documents folders are shown for review one by one. They are never ticked by default, and neither are duplicates, old AI-agent sessions, iPhone backups, virtual-machine images, or the long tail of old downloads.

What happens when you delete something depends on what it is. This is how the app is built today:

- **Your own files go to the Trash (Mac) or the Recycle Bin (Windows), so you can restore them.** That covers large files, old files, old downloads, duplicates, virtual-machine images, uninstalled-app leftovers, orphaned Mac start-up files, old AI-agent sessions, iPhone and iPad backups, iOS update files, macOS installers, and anything you tick by hand in Explore Disk. If moving an item to the Trash or Recycle Bin fails, that item is left alone and the app says so; it does not fall back to deleting it outright.
- **Caches, logs, build output and dependency folders are deleted permanently.** The tool that made them rebuilds them, so the app does not route them through the Trash. The confirmation screen says "Caches are deleted permanently" when any are ticked.
- **A few things are removed by the owning tool's own command**, not by deleting files: Docker prunes, Xcode simulators and runtimes (`simctl`), dead git refs (`git`), and local snapshots (`tmutil` on Mac, `vssadmin` on Windows). These do not go through the Trash.
- **A Windows start-up entry is a registry value, not a file.** Prune saves a `.reg` backup of it to the Recycle Bin first, so double-clicking the backup restores it.
- **Emptying the Trash or Recycle Bin is permanent.** The Trash and Recycle Bin entries in this list exist to do exactly that, and are ticked because you already chose to delete those files.

Moving files to the Trash frees no space until the Trash is emptied; the app reports those bytes separately.

## How to suggest a path

Open an issue or pull request with:

1. The path, and the Mac or Windows version it applies to.
2. What creates it (the app or tool, and what it uses the folder for).
3. How to check it is safe to clear: what is lost, what is rebuilt, and how you confirmed it.

Please do not suggest folders that hold your own work, settings, saved accounts or history. If a folder is only safe in some situations, describe the situation.
